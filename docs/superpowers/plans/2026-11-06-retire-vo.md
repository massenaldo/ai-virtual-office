# Retire `/vo` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove the `/vo` command and everything only it uses, and make `npm run dev:full` the documented way to open the office.

**Architecture:** Deletion plus documentation. `npm run dev` stays as the browser-only demo. No product behaviour changes other than `dev:full` printing the address to open.

**Tech Stack:** Vite, TypeScript, npm scripts.

**Spec:** `docs/superpowers/specs/2026-11-06-office-presence-daily-life-design.md`, section 6.0.

## Global Constraints

- The address to open is exactly `http://localhost:5173`, because `localhost` keeps any layout saved under the old `/vo` link.
- The Vite server stays bound to `127.0.0.1`, with `strictPort`, `allowedHosts` and the `fs.deny` rules unchanged. This is security configuration.
- Browser-only `npm run dev` keeps working as a secondary demo.
- Historical records keep their `/vo` mentions: `docs/milestone-*`, `docs/milestones/`, `docs/superpowers/plans/` and `docs/superpowers/specs/`.
- No new dependencies. Never read, print or ask for an API key.

## Review Focus

1. A person who follows the README from a fresh clone reaches a working office with the backend, at the documented address.
2. Closing or reloading the page under `dev:full` does not stop the server.
3. The `allowedHosts` check still lets the `localhost` address through, so the documented URL does not answer 403.
4. Nothing still refers to a removed file: the build, type check and tests would catch imports, and a text search catches docs and error messages.
